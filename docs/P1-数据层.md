## 几个设计决定（面试会问）

**1. 为什么 Redis 和 MySQL 都要？**
Redis 存"最近 N 条"作为 LLM 的上下文，读得快，会过期也无所谓；MySQL 存完整历史，是权威数据，用于查询、审计和后续的工单关联。两者职责不同，不是缓存和数据库的关系。

**2. 消息分页为什么用游标，不用 `LIMIT offset, size`？**
`LIMIT 10000, 20` 要先扫过前 10000 行再丢掉，越往后翻越慢。游标分页 `WHERE conversation_id = ? AND id < ? ORDER BY id DESC LIMIT ?` 配合联合索引 `(conversation_id, id)`，每页只扫描 size 行。代价是不能直接跳到第 N 页，但聊天记录本来就是"往上滑加载更多"，正好合适。
实现上多查一条（size + 1）来判断是否还有下一页，省掉一次 `COUNT(*)`。

**3. 联合索引为什么是 `(user_id, last_message_at)` 这个顺序？**
查询是 `WHERE user_id = ? ORDER BY last_message_at DESC`：等值条件的列放前面，排序列放后面，索引本身就是有序的，不需要额外排序（不会出现 `Using filesort`）。

**4. 为什么用 `INSERT ... ON DUPLICATE KEY UPDATE`？**
"会话不存在就插入、存在就累加消息数"如果写成先 SELECT 再 INSERT/UPDATE，两个并发请求可能都查到"不存在"，然后一个插入成功、另一个主键冲突报错。一条 upsert 语句由数据库保证原子性。用的是 MySQL 8.0.19+ 的 `AS new` 行别名写法，旧的 `VALUES()` 函数写法从 8.0.20 起已废弃。
知识库切片同理：切片 id 由"标题 + 序号 + 内容前 50 字"算 md5，重复导入同一文档时覆盖，不会产生重复行（幂等）。

**5. 事务边界怎么划？**
- 一轮对话的"会话计数 + 两条消息"放在一个 `@Transactional` 里，不会出现只有问题没有回答的半截记录。
- 知识库导入：先在一个事务里写完所有切片，提交成功后再更新内存索引。写库失败时，内存里不会出现库里没有的数据。
- 落库失败不影响本次回复（回答已经生成，没必要让用户报错），只记错误日志。代价是这一轮可能从历史里缺失，后面用 MQ 异步落库 + 重试来补。

**6. 为什么知识库加载不放在 `@PostConstruct` 里？**
`@PostConstruct` 执行时，Flyway 可能还没建表，第一次启动会直接报"表不存在"。改成实现 `SmartInitializingSingleton`，它在所有单例（包括执行迁移的 Flyway 初始化器）创建完后才调用。

**7. 越权读写**
写别人的会话返回 403；读别人的会话返回 404（和"不存在"一样），避免让人通过状态码探测别人的会话 id 是否存在。
目前 user_id 仍由客户端传入，接入 JWT 之后改为从登录态里取。

## 已知局限（如实说）

- 检索仍然是"全量加载到内存，再算 BM25 和向量分"，适合几千条以内的小知识库；多实例部署时，一个实例导入的文档其他实例要重启才能看到。
- 文档内容修改后，切片 id 会变，旧切片不会自动删除（后续加文档级的版本管理）。
- 情景记忆每次取该用户最近 200 条现算相似度，数据量大了要换成向量库。
- `MemoryManager` 里"写入 → 判断长度 → 压缩"不是原子的，同一会话并发请求会丢消息。**这是下一步要解决的。**

## 本地怎么跑

### 1. 准备 MySQL 和 Redis

Docker 能用的话：

```powershell
docker compose up -d mysql redis
```

Docker 用不了（你的 Docker Desktop/WSL 之前一直起不来），就在 Windows 上直接装：

- MySQL 8.4：官网下载 MSI 安装，装好后执行：
  ```sql
  CREATE DATABASE prismdesk DEFAULT CHARACTER SET utf8mb4;
  CREATE USER 'prismdesk'@'%' IDENTIFIED BY 'prismdesk123';
  GRANT ALL ON prismdesk.* TO 'prismdesk'@'%';
  ```
- Redis：装 Memurai（Windows 版 Redis）或任意 Windows 版 Redis，记下端口和密码。

表不用手动建，应用启动时 Flyway 会自动执行 `V1__init_schema.sql`。

### 2. 配置环境变量

把原来 EchoMindJava 里的 `.env` 复制过来（里面有 DeepSeek key，**不要提交到 git**，`.gitignore` 已经忽略它）。在 IDEA 的运行配置里设置环境变量：

```
SPRING_PROFILES_ACTIVE=deepseek
DEEPSEEK_API_KEY=你的key
REDIS_PORT=6380          # 用 docker compose 起的 Redis 映射在 6380；本机装的一般是 6379
REDIS_PASSWORD=echomind123   # 本机 Redis 没设密码就留空
```

### 3. 编译和测试

```powershell
mvn test          # 或在 IDEA 里右键 ConversationServiceTest 运行
```

### 4. 启动后检查

```powershell
# 1) 表建好了吗、默认知识库导入了吗
#    在 MySQL 里：SELECT COUNT(*) FROM knowledge_chunk;   期望 6 行
#                SELECT * FROM flyway_schema_history;      期望有 V1

# 2) 同一个会话聊两轮
$body = @{ message = "我想申请退款"; user_id = "u1"; conv_id = "c-test" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://localhost:8080/chat -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($body))
$body = @{ message = "退款多久到账"; user_id = "u1"; conv_id = "c-test" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://localhost:8080/chat -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($body))

# 3) 查会话和消息（size=2 时应该返回 next_before_id，再带上它查剩下的）
Invoke-RestMethod "http://localhost:8080/conversations?user_id=u1"
Invoke-RestMethod "http://localhost:8080/conversations/c-test/messages?user_id=u1&size=2"

# 4) 换个用户写同一个会话，应该返回 403
$body = @{ message = "hi"; user_id = "u2"; conv_id = "c-test" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://localhost:8080/chat -ContentType "application/json" -Body $body

# 5) 重启应用后再查知识库统计，数量不变
Invoke-RestMethod http://localhost:8080/knowledge/stats
```

## 简历上这一步可以写什么

> 将知识库、长期记忆、用户画像从 JSON 文件迁移到 MySQL（Flyway 管理表结构），新增会话与消息持久化；消息历史采用基于联合索引的游标分页，会话计数用 `ON DUPLICATE KEY UPDATE` 保证并发下的原子更新，并增加会话归属校验防止越权读写。
